# Открытые вопросы

Незначительные вопросы, по которым принято решение по умолчанию. Работа продолжается; если решение не устраивает — поправить здесь и сообщить.

| # | Вопрос | Принятое решение |
|---|--------|------------------|
| 1 | Можно ли смешивать реальные ЖК/застройщиков с выдуманными рисками в демо-данных? | Нет: демо-объекты (`--demo`) — только вымышленные названия и БИН. Реальные публичные сведения о ЖК (если найдены) идут отдельным CSV для импорта, без каких-либо отметок о нарушениях: зону система посчитает сама по внесённым данным. Иначе «красная» метка у реального застройщика в демо — риск диффамации. |
| 2 | Официальный образ `minio/minio` больше не публикуется (upstream в архиве). | В compose — закреплённая сборка `alpine/minio:RELEASE.2025-10-15T17-29-55Z`. Бэкенд использует только S3 API + Object Lock, на проде можно заменить на любое S3-совместимое хранилище с Object Lock правкой `S3_*`. |
| 3 | Защита входа от перебора. | В v1 нет. До прода: `limit_req` на `/api/v1/auth/login` в nginx + аудит неудачных входов. |
| 4 | Отзыв JWT при смене пароля. | В v1 нет — токен живёт `JWT_TTL_MINUTES` (480). До прода: версия токена в `app_user`. |
| 5 | Неизменяемость на уровне БД обходится суперпользователем. | В dev приложение ходит в БД владельцем. На проде — отдельная роль приложения без UPDATE/DELETE на `evidence`, `audit_log`, `risk_factor_change`; S3-ключ без права обхода governance. |
| 6 | Видимость застройщиков между регионами. | Поиск по полному БИН находит застройщика из любого региона (чтобы привязать к объекту), включая руководителя и телефоны. |
| 7 | Журнал действий для `mio_officer`. | По всем сигнальным карточкам своей территории (а не только «своим»). |
| 8 | `dsu_permit` | = разрешение на привлечение денег дольщиков (ДДУ/дольщики). |
| 9 | Перевод на казахский (UI). | Сделан, требует вычитки носителем. Казахских вариантов в словаре рисковых формулировок пока нет. |
| 10 | Защита от ухода со страницы с несохранёнными правками сигнальной карточки. | Только `beforeunload` + панель «Сохранить/Отменить»; полноценный guard требует перехода на data router. |
| 11 | Жилищный портал АО «КЖК» (homeportal.kz) отдаёт реестр объектов долевого строительства через недокументированный публичный API (`api.homeportal.kz`). | Используем для пилота: снимок от 2026-10-13 в `backend/app/seed_data/pilot/`, плюс команда синхронизации (выключена по умолчанию). Для регулярного использования нужно письменное согласование с АО «КЖК» — до этого автосинхронизация не включается. |
| 12 | Основание «Участие БВУ» в реестре КЖК не имеет отдельного типа документа в модели. | Записывается как `dsu_permit` (разрешение МИО выдаётся при всех трёх основаниях) с основанием в примечании. Гарантия КЖК → `guarantee`. |
| 13 | ЖК с krisha.kz, которых нет в реестре КЖК. | Документ `dsu_permit` со статусом `checking` («требуется ручная сверка»), а не `not_found`: отсутствие в выгрузке не доказывает отсутствие разрешения. Зона таких объектов — жёлтая до ручной сверки. |
| 14 | Календарь 2027 и границы районов. | Календарь 2027 — расчётный по закону, без официальных переносов (перепроверить в декабре 2026). Районы — приблизительные полигоны (официальных границ в открытых данных нет), только для фильтра. |
| 15 | Получатель карточки `mio` — кто вносит результат? | ТЗ называет МИО одним из получателей (внутренняя проверка). Результат по такой карточке вносит `mio_officer`. |
| 16 | Архивировать ли направленную версию PDF? | Да: при «Подтвердить и направить» PDF сохраняется как `evidence` (kind `pdf`) — неизменяемая копия того, что ушло во внешний орган. |
| 17 | Закрытое коллективное обращение навсегда держит объект вне зелёной зоны. | Фактор `complaints` учитывает только незакрытые обращения (в т.ч. коллективные). |
| 18 | `risk_score` пишется при каждом пересчёте, даже без изменений. | Оставлено как есть (полная история); при росте объёма — писать только при изменении балла/зоны/факторов. |
| 19 | Дашборд отдаёт все объекты территории без пагинации. | Для города/области достаточно. Для уровня РК (`territory_id=null`) — добавить кластеризацию/пагинацию при раскатке. |
| 20 | Изменение весов факторов. | Только национальный администратор (без территории): веса едины для всей РК, пересчитываются все объекты. |
| 21 | `key_status`: разрешение на проверке. | `no_permit*` — только если нет ни подтверждённого, ни проверяемого разрешения; иначе `permit_checking`. |
| 22 | Docker Desktop + Ollama внутри WSL: `host.docker.internal` ведёт в Windows, а не в WSL. | В dev в `.env` указывать `OLLAMA_URL=http://<IP WSL>:11434` (`hostname -I`), Ollama запускать с `OLLAMA_HOST=0.0.0.0:11434 ollama serve`. На проде — адрес LLM-сервера в контуре РК. |
| 23 | Правка словаря формулировок и уже сохранённые публикации. | После изменения словаря публикации за последние 90 дней переанализируются автоматически; есть ручной запуск для администратора. |
| 24 | Сырые ответы реестра КЖК (`registry_response`) содержат контакты застройщиков. | Хранятся побайтно как получены (иначе это уже не доказательство). Это публичные данные о юрлицах; в поля карточек контакты не переносятся, в seed (`--demo`) их нет. |
| 25 | Неподтверждённые БИН со стороннего агрегатора (statsnet.co). | В карточку застройщика не вносятся; цитируются в примечании к документу «на проверке» с источником. |
| 26 | Спорные сопоставления krisha ↔ реестр КЖК (Satti City 2, Asyl Tau). | Satti City 2 не связан с записью реестра (совпадение не подтверждено), Asyl Tau связан по номеру разрешения, но с координатами krisha (расхождение 1,6 км отмечено в примечании). |
| 27 | Публикация, привязанная к ЖК автоматически, но с неподтверждённой привязкой (статус «на верификации»). | Не даёт баллов R2/R3/R5 — только флаг «Нужна проверка: привязка не подтверждена». Иначе нечёткое совпадение по слову «ЖК» могло сделать объект красным (найдено ревью). Баллы появляются после подтверждения привязки аналитиком. |
| 28 | Подтверждение результатов ИИ одной кнопкой («Принять»). | Переносятся только находки, найденные в тексте дословно и с уверенностью ≥ 0,5; схема оплаты без подтверждающей цитаты отбрасывается. |
| 29 | Публикация, которую собрал сборщик или прислал гражданин, привязана к ЖК автоматически (по названию или телефону). | Не влияет на балл до подтверждения привязки человеком, даже при высокой уверенности. Сразу засчитывается только привязка через аккаунт, который сотрудник сам связал с объектом. |
| 30 | Сбор реальных публикаций о реальных ЖК и запрет кейса обвинять реальные компании. | Все сборщики и бот выключены по умолчанию и включаются осознанно (`.env`). В материалах сдачи (README, скриншоты, видео) — только вымышленные ЖК. Используемые пути OLX и Krisha robots.txt не запрещает, у t.me robots.txt нет. API OLX и Krisha неофициальные, поэтому частота запросов низкая. |
| 31 | TikTok: автоматический сбор публичных профилей. | Проверено 13.10.2026: без входа `item_list` возвращает пустой ответ, а правила TikTok запрещают обход. Автосбор не делаем, TikTok добавляется по ссылке. |
| 32 | Krisha: текстовый фильтр `_txt_` не подтверждён. | Ищем по фильтрам, которые задаёт сохранённый URL поиска. Отбор по словам делает обычный разбор фраз по полному описанию. |
| 33 | Ответ бота «Проверь ЖК» гражданину. | Только факты реестра на дату (есть или не найдены гарантия КЖК и разрешение МИО, застройщик, стадия) и общий совет «не вносите деньги до проверки». Балл и зона не сообщаются: это внутренняя оценка, а не вывод. |
| 34 | История баллов для «машины времени». | Восстанавливается тем же движком по датам фактов (`trigger=replay`). У стадии и готовности истории нет, поэтому берутся текущие значения. Срез помечен как восстановленный. |
| 35 | Где хранить текст, распознанный с фото. | В конце `ad_post.text` после маркера `[OCR]`. Подсветка, ИИ и смещения фраз работают без изменений, а интерфейс показывает эту часть отдельным блоком. |
| 36 | OLX.kz и Krisha.kz отвечают сборщику защитой WAF (CloudFront 403, SafeLine 468). Браузерный User-Agent её проходит. | Подмену браузера не делаем: это обход правил площадки. Сборщики готовы и проверены на синтетических страницах, по умолчанию выключены. Для работы нужно согласие площадки (белый список адресов или партнёрский API). `COLLECT_USER_AGENT` настраивается. |
| 37 | Krisha: за запуск открываются не больше 20 детальных страниц, а `since` по дате потерял бы объявления сверх лимита. | `since` для Krisha не используется. Открываются только объявления, которых ещё нет в базе; страница из одних известных объявлений останавливает обход. |
| 38 | Отказ от кандидата в источники действует для всех территорий. | Так и задумано: аккаунт не принадлежит территории, а список «не предлагать» общий. Отклонять может сотрудник МИО любой территории, действие пишется в журнал. |
